In multi-application platforms, keeping styling variables in sync between web applications, mobile frontends, and component documentation often leads to copy-paste drift and brittle CSS overrides.

When architecting the ArchLens token system, our core requirement was **zero runtime penalty**: design tokens should exist as single-source JSON declarations and compile directly into native CSS custom properties and typed TypeScript definition files at build time.

---

### The Token Contract: Single Source of Truth

We structure design primitives hierarchically into three tiers:
1. **Global Tokens**: Raw values (`color.slate.900 = "#09090b"`).
2. **Semantic Tokens**: Meaning-based references (`color.surface.canvas = "{color.slate.900}"`).
3. **Component Tokens**: Scoped overrides (`button.primary.bg = "{color.surface.canvas}"`).

```json
{
  "color": {
    "surface": {
      "page": {
        "value": "{color.slate.950}",
        "type": "color"
      }
    }
  }
}
```

---

### Build-Time Generation Pipeline

Using a lightweight compiler transform, our pipeline outputs:
- **`tokens.css`**: Standard CSS variables with dark mode media query overrides.
- **`tokens.d.ts`**: Strict TypeScript literal types for compile-time autocompletion.
- **`tailwind.preset.js`**: Seamless integration with Tailwind configuration without manual hex duplication.

```typescript
// Auto-generated strict types guarantee safety across consumer codebases
export type SurfaceToken = 'page' | 'elevated' | 'overlay' | 'muted';
```

---

### Key Outcomes

By moving token compilation entirely to the build step, consumer applications achieve sub-millisecond styling resolution without shipping heavy CSS-in-JS runtime parsers to end users.
